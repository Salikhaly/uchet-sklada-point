# Локальный вход: исправление no_profile

Если `/api/auth/login` отвечает 200, но `/` уходит на `/login?error=no_profile`,
это означает, что Supabase Auth уже принял пароль, а приложение не смогло прочитать профиль.

В этой версии главная страница читает профиль серверным admin-клиентом, поэтому stale RLS не ломает вход.
Миграция `202608310016_local_auth_profile_repair.sql` идемпотентно добавляет поля режима и восстанавливает policy профиля.

После распаковки:
1. убедись, что `.env` содержит `SUPABASE_SECRET_KEY`;
2. запусти локальный Supabase / выполни миграции;
3. `npm run dev`;
4. логин `Ansar` + пароль существующего Supabase пользователя.
