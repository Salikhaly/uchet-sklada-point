# Интеграция Точки в Ангар

## Структура

`/` — выбор режима.

`/angar` — существующий Ангар, отдельный workspace.

`/point` — Точка, отдельный workspace.

### Точка
- Монитор
- Приёмка: вечерний итог закупки из тетради
- Отгрузка: полноценная складская операция с проверкой остатка
- Продажа: розничная продажа
- В Ангар: атомарное внутреннее перемещение
- Вечерняя сводка: начальная касса, «Принесли за день», фактическая касса, расходы сотрудников, проверка и закрытие
- Остатки
- Журнал
- Отчёты: товары, отгрузки, продажи, расходы по сотрудникам и категориям

### Важные правила

- Вечерняя сводка не просит повторно вводить отгрузки/продажи/перемещения, которые уже проведены.
- Расходы вводятся вечером непосредственно в сводке.
- Расходы не меняют остаток металла.
- Перемещение Точка → Ангар не считается расходом или продажей.
- Перемещение создаёт связанные движения по двум workspace в одной транзакции.
- После закрытия дня операции и расходы на эту дату блокируются до переоткрытия.
- Existing Angar schema/UI are preserved; Point is additive.

## Миграция

Новая миграция:

`supabase/migrations/202608310010_point_workspace.sql`

Она:
- добавляет `profiles.point_workspace_id`;
- создаёт отдельный workspace Точки;
- копирует текущий справочник товаров/контрагентов в Точку для стартовой загрузки;
- добавляет сотрудников, вечерние сводки, расходы и перемещения;
- добавляет защищённые Point RPC;
- создаёт системных контрагентов `Население`, `Розничный покупатель`, `Внутреннее перемещение`;
- обновляет `handle_new_user`, чтобы новые пользователи сразу получали Точку.

## Важное ограничение архива

В переданном архиве существующий `warehouse-app.tsx` обращается к `/api/operations*`, но соответствующие route-файлы в архиве отсутствуют. Этот слой намеренно не переписывался при добавлении Точки, чтобы не менять существующий Ангар без отдельного согласования.
